- GeoJSON export and import with a round-trip report (DESIGNER-10): `GET /api/v1/layouts/{layoutId}/export` (VIEWER+, drafts for editors) returns `application/geo+json` named `castor-<port>-v<N>-<yyyy-mm-dd>.geojson`: a FeatureCollection in CRS84 `[lon, lat]` with 7 decimals, a `castor` member (`schemaVersion`, `port`, `origin`, `frameRotDeg`, `measureSrid`, `versionNo`, `exportedAt`, `exportedBy`) and every feature with its provenance; features from a source that may not be stored (Google Maps) are never written. `POST /api/v1/layouts/{layoutId}/import?dryRun=true|false` (EDITOR+, multipart `file`, `.geojson` or `.json`, 10 MB) takes a FeatureCollection or one Feature: `properties.type` or `castorType` picks the asset type, else a LineString is a FENCE and a Polygon a LAYDOWN_YARD, otherwise the feature is skipped ("Skipped a <geometry> without a Castor type"); a polygon given for a point, box or circle type is placed at its centroid, headings and sizes come from `heading_deg`/`headingDeg`, `length_m`/`lengthM` and so on; a feature id matching an asset id or code of the draft updates that asset, any other creates one (an id of a known asset without a revision in the draft keeps that id, so an export imports back into a blank draft with the same ids and links); provenance from the file, else SURVEY, VERIFIED, today, "Imported from GeoJSON", and a source that may not be stored is refused. Every feature runs through the single-asset save (DESIGNER-03/04 rules), one after another in one transaction, so it is judged against the draft and the features accepted earlier in the file; a dry run does the same and rolls back. Real imports write one `LAYOUT_IMPORTED` audit row plus one row per asset. The report is `{file, added, updated, skipped, skipReasons, roundTrip:{coordinates, maxDifferenceMm}}`; the Westports export imports into a blank draft with the same coordinates (under 10 mm). Versions tab: "Export GeoJSON" for the draft and "Export" on every published version (history "Exported N features as GeoJSON"), "Import GeoJSON" for editors with a dry-run report card ("Import of <file>", counts, round trip, 8 skip reasons and "Show all"), Import and Cancel, toast "N features imported, K skipped", history "Imported N features from <file>" and one undo step, and the help text. The multipart upload is allowed on the import path only (`RequestGuards`); `Content-Disposition` is exposed to CORS. Backend and frontend tests with fixture files in `src/test/resources/geojson-import`.

### Changed

- Faster CI: the backend tests no longer print every SQL statement and DEBUG line (`%test` turns off the dev logging: about 419,000 log lines down to 1,500), the backend job runs the format check and `verify` in one Maven run without packaging the app (`-Dquarkus.build.skip=true`), pulls the PostGIS image while Maven compiles and skips the Testcontainers clean-up container, and the e2e job no longer waits for the backend and frontend jobs.

### Removed

- Screenshot comparison in the e2e suite (JOIN-03): `e2e/visual.spec.ts`, the screenshots in `e2e/responsive.spec.ts`, the `toHaveScreenshot` settings and the manual "Visual baselines" workflow. The responsive layout checks stay.
- 3D rendering in the e2e suite, to keep it fast: the e2e browser runs without WebGL; removed `e2e/gizmo-3d.spec.ts`, `e2e/osm-buildings.spec.ts`, `e2e/acceptance/02-footprint-3d.spec.ts`, the 3D half of the drag spec (now `04-drag-2d.spec.ts`), the 3D selection test of the split view, the Monitor asset pick, the frame rate, draw call, 12-angle sweep and memory tests of `performance.spec.ts` (the API budgets stay), the "Performance soak" workflow and the test hooks `window.__castorScene` and `window.__castorGizmo` (`scene-probe.tsx`, `test-hooks.ts`) (JOIN-04).

### Fixed

- The Design palette showed coloured squares instead of the 3D thumbnails: the asset-type API sends `model_key` as the lower-case code and the model library is keyed by the upper-case code. `getModelSpec` now accepts either.
- Palette thumbnails went blank after a few groups were opened (and the 3D stage could lose its context): every tile called `webglAvailable`, which opened a new WebGL context each time until the browser dropped the oldest ones, the thumbnail renderer among them. The check now runs once and gives its probe context back, and the thumbnail renderer starts a new context if its own was lost.
- The Westports demo layout was loaded in any environment with `castor.layout.seed-on-start` (default true); it is now loaded only in local, dev and test (`CastorConfig.layoutSeedActive`) (CORE-04).
- `castor_validation_duration`, `castor_publish_count`, `castor_import_count` and `castor_spatial_query_duration` were registered but never recorded; validation, publish, GeoJSON import and the PostGIS placement queries now report them (SETUP-04).
- A failed request is reported to the browser console with its `requestId` and `errorId`, and error cards show "Error id: <id>" to quote when asking for help (SETUP-04).
- Berths draw their crane rails when a rail quay crane stands on them, and storage pads draw their fill by the cargo's storage form from the catalogue (piles, stacks or silos) up to the pad's maximum stacking height (REPLICA-03).
- A click within the 7 px hit tolerance outside a polygon's outline selects it on the 2D map, as lines and berths already did (DESIGNER-06).
- More menu "Verify accuracy" shows its description "Check control points and accuracy labels" (DESIGNER-11); `useAccuracyReport` hook (CORE-02).
- The database rule suite (`DatabaseRulesIT`) runs: a point berth, a shape outside the extent, a self-intersecting polygon, SRID 3857, a duplicate code, heading 360, a change to a published revision, a second draft, a plaintext password, bcrypt cost 10 and an upper-case duplicate username are each refused by the database (SETUP-09). Removed the stray empty file `-dev+` from the repository root.
