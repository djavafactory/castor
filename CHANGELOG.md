## [Unreleased]

### Added

- Layers, tool strip, help, level of detail, envelope and accuracy outlines (REPLICA-07): "All layers" popover (300 px, "Show <name>" and "Isolate" per row, "Show all", Design locks with "That layer is locked. Unlock it in Layers to edit.") with layer membership from `asset_type.category`; shared tool strip (camera dropdown, zoom, rotate, reset, Cargo, Containers and Labels toggles, panel, fullscreen in Monitor, More menu with "Help and legend" and "Verify accuracy" in Design) replacing the camera overlay and the Help button; help popover with accuracy swatches, keyboard table and attribution; shortcuts 1-5, P, F, L, ?, Esc plus the Design keys A, R, M, Backspace, Ctrl+Z and Ctrl+Y; plain coloured boxes beyond 1,500 m (300 m cells), `InstancedMesh` for repeated assets of one model and size; orange envelope boxes (footprint x drawn height, at least 0.3 m) and accuracy outlines (APPROXIMATE dashed); the model library is checked against its envelopes (pump station, parking yard, exclusion zone and coil yards now respect a lower declared height). Frontend only.
- Layout versions, Westports seed and layout read API (CORE-04): `layout.layout_version` (DRAFT/PUBLISHED/SUPERSEDED/DISCARDED, one draft and one published per port), permanent `layout.asset` identities, `layout.asset_revision` with PostGIS geometry, guard trigger (only drafts change, geometry kind per asset type, inside the port extent), `layout.copy_revisions`, computed measurements view, and typed detail tables with checks (V5); Hibernate entities with JTS geometry; `Footprints`, `StoragePadCapacity`, `LayoutFeatureValidator` in the domain; the shared `GeoJsonMapper` (7 decimals, [lon, lat]); `GET /api/v1/ports/{code}/layouts/current` and `/draft`, `GET /api/v1/layouts/{id}` and `/assets/{assetId}` with ETag and 304; `LayoutSeedJob` loads `seed/westports/layout-v1.geojson` (301 synthetic assets, 82 SERVES and 5 FEEDS links) as published version 1 in local, dev and test only; `scripts/generate-westports-layout.mjs` regenerates that file.
- Reference data and catalogue (CORE-02): `ref` tables (port with frame and checks, data sources, accuracy classes, categories, palette groups, surfaces, cargo and ship catalogue, control points, import batches, reference features) and the Westports seed (V3); `layout.asset_type` with all placeable types including EXCAVATOR and MOBILE_CONVEYOR_LOADER (V4); `OsmImportJob` for the OpenStreetMap background; VIEWER+ endpoints `GET /api/v1/ports`, `/ports/{code}`, `/ports/{code}/control-points`, `/ports/{code}/reference-features`, `/asset-types`, `/catalogue` with ETag, 304 and gzip; frontend zod-validated data hooks, mutation hooks with optimistic updates and rollback, and `QueryBoundary`.
- Static container terminal (REPLICA-04): `CONTAINER_YARD` fill generated from the yard code (FNV-1a + mulberry32), size, max tiers and design fill (6.3 m bays, 2.7 m rows, 2.4 m aisle after every 7th row, 20/40 ft boxes stacked exactly on each other), drawn as one InstancedMesh per box size per yard on a #B9B7AE pad, with TEU caption; `ContainerTerminalLayer` for yards plus STS cranes and RTGs behind the "Containers" switch. Feature flag `castor.features.containers` / `VITE_FEATURE_CONTAINERS` (default on); off: no Containers layer, yards, cranes or TEU figures. Frontend only; no container field in shared types.
- 3D model library part 2 (REPLICA-03): 37 more procedural models, so all 56 asset types render: buildings (extruded drawn footprint, gabled warehouse with dock doors and canopy, transit shed, covered bay), storage (pad with slot grid and design-fill piles, stacks or silos, coil yards on a 3.4 / 3.2 m grid, stockpile bay), bulk (silo, hopper, transfer tower, conveyor on trestles), liquid (tank, bund wall, pump station, pipeline, pipe rack, loading arm), marine (berth strip with crane rails and label, fender, bollard, RoRo ramp), gates, roads and parking, and zones (translucent exclusion and drainage fills, fence, boundary, surface). These models are parametric: drawn true to the asset footprint, path, size and details, never scaled. `buildLayoutMeshes` merges a whole layout into one mesh per material (336 assets: under 120 draw calls). Frontend only.
- 3D model library part 1 (REPLICA-02): one `model_key` registry of 19 low-poly procedural models (8 cranes incl. quay crane on rails and STS, 6 handling machines incl. excavator and mobile conveyor loader, 5 vehicles on a shared truck base), merged per colour (at most 6 draw calls each), matte, drawn exactly at the declared size with origin at the footprint centre, +X heading and named pivots; `AssetVisual` rescales by length, width and height ratio at once, shows a neutral #C9BFA3 box with label for unknown keys and a flat uncertainty ring for PARKED mobile equipment; palette thumbnails rendered once off-screen (168 x 120, FOV 28) and cached, shown at 84 x 60 in the Design asset palette. Frontend only.
- OpenStreetMap buildings in 3D (REPLICA-01): the committed OSM reference file (127 buildings, 504 roads) is loaded by the CORE-02 import job; building features carry `area_m2` (measured in the port CRS), `source` and `accuracy` next to `height_m`; 3D stage with all buildings in one merged mesh (walls #9AA3AD, roof 35 % lighter, rooftop unit on buildings above 12 x 10 m, face-to-building index for picking), hover text, read-only details and the "Buildings (OSM)" switch in All layers.
- App release versioning: one version in the root `VERSION` file, kept equal in `backend/pom.xml` and `frontend/package.json` (CI check); build stamps with version, 7-character commit and UTC build time (untagged builds are `X.Y.Z-dev+commit`, tag `vX.Y.Z` builds exactly `X.Y.Z`); public `GET /api/v1/version`; version in the login card footer and the Help popover, with `(server v<x>)` when frontend and server differ (SETUP-11).
- Coordinate system (CORE-01): backend `QuayFrame`, `QuayShapes` (rect, 48-segment circle), `CoordinateRounding` (7 decimals, largest move in mm) and PostGIS `Measurements` via `ST_Transform` to `measure_srid` (EPSG:3380); frontend `src/lib/geo` (frame, scene axes, shapes, local measures, self-intersection, Vincenty distance and bearing, `usePortFrame`); shared `fixtures/coordinates.json` (generated by `scripts/generate-coordinate-fixtures.mjs`) checked by both suites.
- Login, users and roles, app shell: `security` and `audit` tables (V2), HTTP Basic against `security.user_account` with bcrypt cost 12, roles VIEWER/EDITOR/PUBLISHER/ADMIN, `GET /api/v1/me`, first-admin bootstrap, demo users and `GET /api/v1/auth/demo-users` (local/dev only), account lockout, auth events; login page with demo user selector and version footer; two-row app shell with Monitor/Design switch and right panel (SETUP-12).
- Database baseline: Flyway V1 (PostGIS, schemas `ref`, `layout`, `audit`, `security`), `castor_flyway` and `castor_app` roles with an append-only audit schema, Hibernate `validate` (SETUP-07).
- Backend skeleton: Maven multi-module build, `castor-core` Quarkus service with health, OpenAPI, metrics, JSON logging, hexagonal packages with ArchUnit rules, Problem Details errors and HTTP hardening (SETUP-04).
- Repository layout, ignore rules, editor config, CODEOWNERS, PR template and Dependabot config (SETUP-02).
- Phase 1 scope, rules and definition of done (SETUP-01).
